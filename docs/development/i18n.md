# Frontend language catalogs

The English editor message objects in `frontend/src/editor/**/strings.ts` remain the source of truth, including their function signatures. `frontend/scripts/extract-i18n.mjs` inventories the static keys in `src/i18n/en.json`; `frontend/scripts/extract-function-fragments.mjs` inventories the English function bodies and message fragments. Non-editor JSX and simple object labels are extracted into the `app.<English text>` key space by the one-time migration scripts in `frontend/scripts/extract-app-{jsx,properties}.mjs`. Do not re-run those migration scripts casually on already migrated files.

`src/i18n/catalog.ts` reads the active locale through a proxy, so editor `t.foo` call sites keep their type and English default. The two Chinese resource pairs (`zh-*.json`, `functions-zh-*.ts`) are imported lazily: English visitors do not download them. Function translations preserve argument names, conditional branches and interpolation; `plural` returns the same Chinese unit for all counts. English remains the fallback for an absent translation. `src/i18n/locale.ts` detects `navigator.languages`, persists an explicit choice in localStorage, updates `<html lang>`, and notifies the app. The initial catalog is loaded before React renders. Changing the language in the marketing header or Settings → Accessibility loads the requested catalog before switching.

The generated function files are translation drafts, **not a guarantee of native-language quality**. Review their actual output in context, especially fragments around arbitrary names, durations, accessibility labels and product terminology; do not assume key parity means translation quality. Taiwan terminology uses 檔案、影片、設定、範本、字型、圖層、復原. Do not translate stable API identifiers, dimensions or format tokens. Keep both static and function key inventories in sync; `src/i18n/locale.test.ts` checks parity and language detection.

Run `node scripts/extract-i18n.mjs` from `frontend/` after changing English editor strings, then update both Chinese catalogs and function files and run `npm test -- src/i18n/locale.test.ts`. Full validation is `make lint`, `cd frontend && npm test && npm run build` with Node.js 22.
