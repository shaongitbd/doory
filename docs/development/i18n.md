# Frontend language catalogs

The English editor message objects in `frontend/src/editor/**/strings.ts` remain the source of truth, including their function signatures. `frontend/scripts/extract-i18n.mjs` inventories the static keys in `src/i18n/en.json`; `frontend/scripts/extract-function-fragments.mjs` inventories the English function bodies and message fragments. Non-editor JSX and simple object labels are extracted into the `app.<English text>` key space by the one-time migration scripts in `frontend/scripts/extract-app-{jsx,properties}.mjs`. Do not re-run those migration scripts casually on already migrated files.

`src/i18n/catalog.ts` reads the active locale through a proxy, so editor `t.foo` call sites keep their type and English default. The German resource pair (`de.json`, `functions-de.ts`) and the two Chinese resource pairs (`zh-*.json`, `functions-zh-*.ts`) are imported lazily: English visitors do not download them. Only the selected locale is loaded. Function translations preserve argument names, conditional branches and interpolation; German functions use singular for a count of 1 and plural otherwise; Chinese uses the same unit for all counts. English remains the fallback for an absent translation. `src/i18n/locale.ts` detects `navigator.languages` (including `de`, `de-DE`, `de-AT` and `de-CH` as `de`), persists an explicit choice in localStorage, updates `<html lang>`, and notifies the app. The initial catalog is loaded before React renders. Changing the language in the marketing header or Settings → Accessibility loads the requested catalog before switching.

Relative times use `Intl.RelativeTimeFormat` with the active locale and a localized “just now” label in `src/lib/time.ts`. This only changes display text, never stored timestamps or API values.

Catalog parity covers inventoried messages; it does not detect hardcoded UI copy that bypasses `msg` or `localized`.

Key parity does not prove translation quality: when you add or change a string, review the German and Chinese output in context, especially fragments around arbitrary names, durations, accessibility labels and product terminology. Taiwan terminology uses 檔案、影片、設定、範本、字型、圖層、復原. Do not translate stable API identifiers, dimensions or format tokens. German uses informal **Du** and the terms Einstellungen, Vorlage, Ebene, Rückgängig, Wiederholen, Speichern and Teilen. Preserve user content, filenames, API identifiers, interpolation expressions and format tokens. Review composed sentence fragments in their rendered context, as German word order can differ from English.

Built-in metadata resolves translated labels through getters when displayed. `writableMetadata` adds setters so an extension can still assign a label or description; an explicit assignment becomes a plain property and remains unchanged across languages. The mounted editor subscribes to locale changes and rerenders without replacing its engine or re-registering entries. Derived labels cached in a memo must include the active locale as a dependency. Keep extension-provided labels and overrides intact; do not use a global registry reset to refresh translations. This does not change the app router lifecycle.

Non-editor messages can use `msg('Delete “{title}”?', { title })`. Add the same key and placeholder names to every static catalog, including `en.json`. Substitution is a single pass, so braces inside user-provided values are preserved. Reuse existing keys before adding messages. Known audio failure codes map to localized UI messages; raw internal exception text is not displayed.

Keep all static and function key inventories in sync; `src/i18n/locale.test.ts` checks parity and language detection.

Run `node scripts/extract-i18n.mjs` from `frontend/` after changing English editor strings, then update the German and both Chinese catalogs and function files. Do not run `generate-locale-functions.mjs` for German: it generates Chinese fragments only; German functions are maintained as complete messages.

Run `npm test -- src/i18n/locale.test.ts src/i18n/german.test.ts src/lib/time.test.ts` from `frontend/`. These check exact key parity against `en.json` and `functions.json`, static placeholders, function signatures, existing conditions and content interpolations (including multiplicity), German plural forms, locale priority, switching, persistence and relative times. `npm run e2e -- language.spec.ts` checks both language selectors, persistence after reload, German browser detection and that English startup leaves German bundles unloaded. Additional rendered coverage is in `src/pages/germanLocalization.test.tsx`; `src/editor/audio/messages.test.ts` checks error-code mapping without internal-message leakage. `src/editor/builtins/localization.test.tsx` checks registration identity and extension overrides. `npm run e2e:editor -- language.spec.ts` checks a mounted editor switching English → German → English, including its open menu, tool labels, document, title and undo history, independently of app routing.

The app browser tests use the mocked API; set `PW_CHROMIUM` to your Chromium binary if needed. Full validation is `make lint`, `cd frontend && npm test && npm run build` with Node.js 22.
